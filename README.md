## HackAlem — логистика «Электрокомплект»

### Для жюри: какую задачу решаем

QORAI помогает закупщику увидеть прогноз продаж по товару, сравнить его с простым средним и подготовить объяснимый черновик заказа поставщику. Источник, дата и ограничения видны рядом с результатом; отсутствие данных не превращается в уверенную рекомендацию.

Стек: Python, openpyxl, детерминированное расчётное ядро, FastAPI/uvicorn и браузерный интерфейс без платного LLM в вычислениях. Исходники Excel читаются без изменения; реальная отправка заказа поставщику не выполняется.

Работают CLI, API и браузерный путь: прогноз, историческое сравнение, условная закупка по явно введённой политике, календарь, черновик и CSV. Основные действия и desktop-компоновка проверены; [визуальная проверка](docs/design-qa.md) фиксирует отличия от Stitch и непроверенную мобильную компоновку. «Самообучение», ERP-проводки и онлайн-склад не реализованы.

Команды ниже выполняются из корня этого репозитория. Не используйте публичный адрес привязки: авторизации в локальном демо нет. Деплой не выполнялся; текущий объём — ноутбук и конкурсный репозиторий.

[API-контракт](docs/API_CONTRACT.md) фиксирует интерфейс параллельной разработки. Итоговые проверки будут отмечены отдельно, а не подразумеваются наличием кнопок.

Обсуждённая концепция и решения владельца сохранены в [едином плане](docs/LOGISTICS_PLAN.md).
План включает прогноз спроса, закупки, бронирование, партии, задержки поставок и документально подтверждённые складские движения.

## Быстрый запуск расчётного среза

Используйте Python3.13 (проверен локально3.13.14, `.python-version` закрепляет ветку3.13 для хостинга). Версии библиотек перечислены в `requirements.txt`.
Публичные исходники организатора можно получить автоматически: helper скачивает ровно два закреплённых архива, проверяет SHA256 архивов и всех12 XLSX и безопасно распаковывает их. Бизнес-данные не генерируются и в Git не добавляются. Если исходная папка `04_Excel` уже есть, её можно использовать вместо загрузки.

```powershell
Set-Location '<папка клона>/hack-2dfc4dce-planp'
py -m pip install -r requirements.txt
py scripts/bootstrap_data.py --output-dir data/issued
$env:HACKALEM_DATA_DIR = (Resolve-Path 'data/issued').Path
$env:HACKALEM_DATA_ROOT = $env:HACKALEM_DATA_DIR  # совместимость тестов импортёра
py -m uvicorn smartbuyer.app:app --host 127.0.0.1 --port 8765
```

Откройте `http://127.0.0.1:8765`. Первый запрос читает Excel; последующие используют снимок. Кнопка «Перечитать Excel» перечитывает только настроенную папку; при ошибке сохраняется прошлый исправный снимок. Повторный bootstrap проверяет уже существующий набор, не перезаписывая неизвестные файлы. Без источников приложение показывает ошибку, не генерирует замену. На Linux/macOS используйте `python` вместо `py` и `export HACKALEM_DATA_DIR=data/issued` из корня репозитория.

CLI и тесты — из второго терминала с теми же переменными:

```powershell
py -m smartbuyer.cli --data-dir "$env:HACKALEM_DATA_DIR" --target 2026-10 --sku ATN544045 --format json
py -m smartbuyer.cli --data-dir "$env:HACKALEM_DATA_DIR" --target 2026-10 --sku ATN544045 --format csv
py -m pytest -q
node --check web/app.js
node web/app.test.cjs
```

Node нужен только для проверки frontend helpers, не для запуска приложения. Последний прогон после ребрендинга:18 helper assertions PASS; они не заменяют браузерные проверки.

Подготовлен переносимый запуск `py -m smartbuyer.serve` с портом из `PORT` и безопасной локальной привязкой по умолчанию; инструкция Python/Docker: [DEPLOYMENT](docs/DEPLOYMENT.md). Docker-сборка не проверена (CLI Docker отсутствует), хостинг настраивает владелец; публичного URL пока нет. Внешний запуск требует явного домена/привязки и получения исходников build-helper либо отдельным томом. Данные в Git и Docker-образ не входят.

Без `--sku` обрабатываются все позиции. CLI пишет только UTF-8 stdout; ошибки — stderr и exit2 без traceback. Сам не создаёт выходных файлов и не меняет исходные книги.
`--as-of YYYY-MM-DD` может уменьшить дату отсечения, но не продвинуть её позже даты выданного набора. По умолчанию используется 22.09.2026 из имён файлов, не дата компьютера и не доказательство live-склада.

## Проверка за несколько минут

1. Откройте приложение, проверьте дату источников 22.09.2026 и число прочитанных файлов; это не остаток на текущий момент.
2. Найдите `ATN544045`: сравните два прогноза и MAE на одних исторических месяцах. Сезонный метод не обязан выигрывать.
3. Оставьте закупочную политику пустой: заказ должен быть заблокирован с причинами, не стать нулевым «готовым» заказом.
4. Для условного сценария явно введите L/H, страховые дни, MOQ и подтвердите отчётный остаток/режим обычных продаж. Это ваши настройки, не найденные факты компании. Проверьте происхождение чисел и риск до новой поставки.
5. Если в источнике есть положительная партия, задайте её ETA явно и сравните задержку; новый приход не добавляется. Без достаточной даты сценарий блокируется. Excel и исходный остаток не меняются.
6. Скачайте прогноз или положительный условный заказ: CSV должен совпадать с экранным расчётом, сохранять статус/единицы/источник. Два сценария одного SKU вместе не экспортируются. Отправки поставщику нет.

Для HTTP-проверки без готового UI: `http://127.0.0.1:8765/api/health` и `/api/bootstrap`; остальное — [API-контракт](docs/API_CONTRACT.md). Browser-приёмка отмечается отдельно от API.

## Метод и ограничения результата

- Каждый SKU рассчитывается отдельно: прошлогодний сопоставимый месяц × динамика трёх полных месяцев; рядом простой метод среднего дневных скоростей 12 полных месяцев.
- Последние шесть полных исторических месяцев проверяются одинаково для обоих методов; неполные месяцы исключены. MAE/Bias — в единицах конкретного SKU; общий MAE смешанных товаров не выводится.
- `calculation_status=ok` означает только успешную арифметику. `forecast_status=provisional`: месячный источник пока не согласован с операциями, неизвестные значения не заполнены нулями. История — наблюдаемые продажи, не очищенный истинный спрос.
- CLI остаётся отчётом прогнозов: закупка там `blocked/null`. В API пустая политика также блокирует заказ. После явного ввода параметров допустим только `provisional`-сценарий обычных продаж по AZ: не полный план клиентских обязательств. Даты дефицита — условная проекция, не доказанный факт склада.
- `auto` в закупочном сценарии выбирает меньший MAE на общих исторических месяцах при наличии минимум трёх; иначе непроверенный fallback к среднему при доступной истории. MAE набора выбора не доказывает будущую точность выбранной модели.
- Отчётная партия с неизвестной датой требует явной сценарной ETA. Новая закупка приходит через введённый полный срок L, покрывает H дат, учитывает страховую политику/MOQ/кратность. До её прихода дефицит не исправляется задним числом. `planned_order_date` — дата размещения сценария, не вычисленный крайний срок.
- Отчётные AX/AY/AZ передаются без повторного вычитания резерва. Для IEK начало месяца не подменяет текущий остаток; ETA без года не становится точной датой.
- JSON и CSV используют один результат, сохраняют происхождение/дату/единицы/статусы/причины. CSV защищает текст от формульных префиксов; null в табличном экспорте — пустая ячейка, не0.
- Только выданные данные: прежнее придуманное бизнес-демо отменено. Наличие Python-тестов не доказывает улучшения прогноза: на проверенном выбранном SKU сезонный кандидат уступил простому среднему по MAE.
- Требования stockout-компенсации и обработки разового заказа одного клиента полностью не доказаны: нет дневной доступности/clientID, операции не примешиваются к месячной базе. Экономия и весь кейс не объявляются достигнутыми.
- Desktop-first путь проверен в браузере. Mobile NOT VERIFIED: инструмент не применил узкий viewport; responsive CSS не выдаётся за доказанную мобильную готовность.
