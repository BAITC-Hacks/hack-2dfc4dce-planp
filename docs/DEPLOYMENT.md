## Данные перед запуском

Автоматический способ для native Python: `python scripts/bootstrap_data.py --output-dir data/issued`. Helper скачивает два публичных архива организатора по фиксированным адресам, сверяет pinned SHA256 обоих архивов и12 исходных XLSX, проверяет имена/безопасность ZIP и не перезаписывает неизвестный существующий набор. API-ключ или авторизация Drive не нужны. Архивы побайтово совпали с уже выданными файлами; новый датасет не создаётся.

Возможен и внешний read-only том с имеющейся папкой `04_Excel`. Сохраните имена и подпапки `IEK`/`Systeme electric`. `HACKALEM_DATA_DIR` указывает на набор, например `data/issued` относительно корня запуска или абсолютный путь тома. Приложению нужны только права чтения; Docker запускается с UID/GID`10001:10001`.

Исходники, ключи и `.env` не входят в образ. `.dockerignore` разрешает только код, статические файлы и список зависимостей; Dockerfile не копирует данные. Загрузка файлов через API не реализована. Без доступных источников `/api/health` возвращает `dataset_loaded=false`, а `/api/bootstrap` — понятную ошибку 503. Успешная загрузка проверяется через `/api/bootstrap`, не только health.

## Настройки процесса

| Переменная | По умолчанию | Для хостинга |
|---|---|---|
| `HACKALEM_DATA_DIR` | Локальная папка источников; `/data` в образе | `data/issued` из корня проекта после bootstrap либо путь внешнего тома |
| `HACKALEM_ALLOWED_HOSTS` | Только `localhost`, `127.0.0.1`, `::1` | Точные имена доменов через запятую, например `demo.example.com`; без схемы, порта или `*` |
| `HACKALEM_BIND_HOST` | `127.0.0.1` | `0.0.0.0` для контейнера/хостинга; требует явного внешнего разрешённого домена |
| `PORT` | `8765` | Порт, выданный хостингом |
| `HACKALEM_PUBLIC_ORIGIN` | Origin должен точно совпадать с URL входящего запроса | Явный публичный HTTPS origin за TLS-прокси, например `https://demo.example.com`; его хост должен быть в `HACKALEM_ALLOWED_HOSTS` |

Приложение проверяет точный Host; поддомены автоматически не разрешаются. Без `HACKALEM_PUBLIC_ORIGIN` Origin должен совпадать со схемой, хостом и портом входящего запроса. За TLS-прокси задайте один точный `HACKALEM_PUBLIC_ORIGIN`: присутствующий заголовок Origin будет сравниваться строго с этим значением, даже если прокси обращается к приложению по HTTP. В значении запрещены путь (включая завершающий `/`), credentials, query и fragment. Для веб-интерфейса используйте именно этот канонический публичный адрес; второй разрешённый Host сам по себе не разрешает второй Origin. Запросы без Origin, например проверка процесса, по-прежнему проходят проверку Host.

Прокси должен сохранять публичный Host. Для этой проверки не нужно угадывать его IP или задавать `FORWARDED_ALLOW_IPS=*`; доверие к forwarded-заголовкам не расширяется. Render документирует [завершение TLS на edge и HTTP до процесса](https://render.com/tutorials/web-service-vs-static-site/web-services), поэтому для Render используется явный публичный HTTPS origin. `local_only` в health означает, что список разрешённых хостов ограничен локальными именами; это не проверка сетевого экрана.

В MVP нет авторизации: список Host/Origin защищает границу приложения, но не ограничивает круг пользователей по личности. Если данные не предназначены для открытого доступа, используйте приватный доступ хостинга или авторизацию на его reverse proxy до публикации.

## Запуск без Docker

Используйте Python3.13, зависимости и переменные окружения в настройках хостинга. `.python-version` задаёт поддерживаемую Render частичную версию; не полагаемся на более новый непроверенный default. [Официальная настройка версии Python](https://render.com/docs/python-version). Команда сборки:

```sh
python -m pip install -r requirements.txt && python scripts/bootstrap_data.py --output-dir data/issued
```

Команда запуска из корня репозитория:

```sh
python -m smartbuyer.serve
```

Локальный запуск этой команды без дополнительных переменных слушает только `127.0.0.1:8765`. Для внешнего сервера задайте `HACKALEM_BIND_HOST=0.0.0.0` и точный публичный домен в `HACKALEM_ALLOWED_HOSTS`. `PORT` подставляется из окружения без shell-обёртки.

## Render Free

Ниже — воспроизводимые настройки Render Free Web Service с Python; фактическая публикация и проверенный адрес описаны выше. PostgreSQL не нужен: MVP читает выданные XLSX, а результаты расчётов держит в памяти. Порядок запуска основан на официальных инструкциях [Render для FastAPI](https://render.com/docs/deploy-fastapi) и [ограничениях Free](https://render.com/docs/free).

1. Создайте Web Service для этого репозитория; `.python-version` закрепляет Python3.13. Тариф/домен выбирает владелец.
2. Build Command: `python -m pip install -r requirements.txt && python scripts/bootstrap_data.py --output-dir data/issued`. Start Command: `python -m smartbuyer.serve`.
3. Установите `HACKALEM_BIND_HOST=0.0.0.0`. Скопируйте фактическое имя домена созданного сервиса в `HACKALEM_ALLOWED_HOSTS`, например имя вида `your-service.onrender.com`, без `https://` и пути. Задайте `HACKALEM_PUBLIC_ORIGIN=https://your-service.onrender.com` с тем же фактическим доменом, без завершающего `/`. Для собственного домена явно добавьте его в allowlist и выберите его как публичный Origin. После изменения окружения выполните deploy/redeploy; wildcard не используется.
4. Оставьте `PORT` под управлением Render. Задайте `HACKALEM_DATA_DIR=data/issued`: start выполняется из корня исходников, куда build-helper получил все12 файлов.
5. Укажите `/api/health` как проверку процесса. После deploy отдельно проверьте `/api/bootstrap`, расчёт и экспорт через настроенный публичный HTTPS origin.

На Free нет постоянного диска. Файлы воспроизводимо доставляет build-helper при новой сборке; простая ручная загрузка в временную среду не заменяет этот шаг. Реальную доступность Google Drive из выбранного хостинга и наличие набора после deploy нужно проверить владельцу. Исходные XLSX и токены не добавляются в репозиторий или Docker-образ; `data/` игнорируется Git.

Free-сервис может засыпать при отсутствии запросов; первый запрос после пробуждения будет медленнее. Рестарт сбрасывает рассчитанные `result_id`. Один worker и одна реплика обязательны. Локальный расход памяти не доказывает пиковый расход на Render; загрузку источников нужно проверить уже в выбранной среде.

## Docker

Сборка из корня репозитория:

```sh
docker build -t qorai .
```

Пример для Linux-сервера за локальным reverse proxy. Сначала замените путь к источникам и домен на фактические. Привязка опубликованного порта к `127.0.0.1` оставляет внешний доступ под контролем reverse proxy:

```sh
docker run --rm --name qorai \
  -p 127.0.0.1:8765:8765 \
  --mount type=bind,src=/srv/hackalem/04_Excel,dst=/data,readonly \
  -e HACKALEM_ALLOWED_HOSTS=demo.example.com \
  -e HACKALEM_PUBLIC_ORIGIN=https://demo.example.com \
  -e HACKALEM_BIND_HOST=0.0.0.0 \
  -e PORT=8765 \
  qorai
```

Для управляемого хостинга настройте аналогичный внешний том `/data`, переменные окружения и выданный порт через его панель. Образ сам по себе не содержит Excel. `EXPOSE 8765` — описание стандартного порта; фактический слушающий порт задаёт `PORT`.

## Проверка и ограничения

После запуска откройте `/api/health`, затем `/api/bootstrap` через фактический домен. Должны загрузиться 12 источников. Проверьте один расчёт и CSV, затем `/api/reload`: старый `result_id` должен отклоняться. Запросы с чужими Host/Origin должны возвращать 403.

Запускайте ровно один worker и одну реплику. Снимок Excel и рассчитанные `result_id` хранятся в памяти процесса: рестарт и успешный reload их сбрасывают. Несколько реплик или workers потребовали бы общего хранилища, которого в этом MVP нет. Размер памяти и время первоначального чтения проверьте на выбранном тарифе с фактическими 12 файлами.

Native Python-публикация проверена выше. Docker build по-прежнему не выполнен; локальные проверки и публичный smoke не доказывают производственную отказоустойчивость.
